# ADR-0006. Мова й технологічний стек шлюзу периферії

## Статус
Прийнято, 2026-11-22

## Контекст
Шлюз — найважливіший складник за пропускною здатністю: він задає Θ і буфер. Вимоги до
нього: безперервна робота, буфер на диску, обмежений процесор вузла (0,25 CPU) і
пам’ять (128 МБ). Виміряно: ≈ 20–25 МіБ пам’яті, 17–19 % CPU на ≈ 935 повідомлень/с,
Θ ≈ 935 повідомлень/с (обмежена модельною смугою ланки 1000 кбіт/с, а не процесором).
Потреба однієї лінії — 3–30 повідомлень/с.

## Варіанти
1. Python, paho-mqtt, SQLite: швидка розробка, одна мова з емулятором і підписником,
   зрозумілий код буфера.
2. Go: менше навантаження на CPU і пам’ять, одна статична збірка, зручна конкуренція;
   довша розробка.
3. Міст Mosquitto (`connection`, `persistence true`) замість власного шлюзу: без коду,
   але без керування місткістю буфера та політикою переповнення.

## Рішення
Обрано варіант 1: Python, paho-mqtt, SQLite. Запас за потребою лінії — понад 30 разів
(Θ / 30 ≈ 31), пам’ять використовується на ≈ 20 % ліміту.

## Наслідки
+ Простий код (≈ 100 рядків), легко змінювати політику буфера й перевіряти експериментом.
+ Ресурсів вистачає: CPU ≈ 70–75 % квоти на Θ, пам’ять ≈ 20–25 з 128 МіБ.
− Інтерпретатор Python споживає більше CPU і пам’яті, ніж Go чи C; наступним вузьким
  місцем стане процесор шлюзу (≈ 1300 повідомлень/с за екстраполяцією, не виміряно).
− Для багатьох ліній на одному слабкому вузлі варто перейти на Go (лекція 11); умова
  перегляду — потрібне λ понад ≈ 0,5 · Θ на один шлюз.
