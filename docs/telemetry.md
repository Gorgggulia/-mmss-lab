# Телеметрія: канал сенсорних даних

## Теми

Тема має чотири рівні: `корпус/лінія/пристрій/вид`, наприклад `k1/line1/vib-1/tele`.

| Рівень | Значення | Приклад |
|---|---|---|
| 1 | корпус | `k1` |
| 2 | виробнича лінія | `line1` |
| 3 | пристрій | `vib-1`, `speed-1`, `temp-1` |
| 4 | вид повідомлення | `tele` (телеметрія), `state` (стан) |

- Телеметрія `…/tele`: QoS 0 (утрату окремого показу виявляє порядковий номер `seq`).
- Стан `…/state`: збережене повідомлення (`retain`) `online`; заповіт `offline`
  брокер публікує сам, якщо емулятор зникне без від’єднання. QoS 1.
- Підписник використовує підписку `k1/+/+/tele` (QoS 1).

## Схема повідомлення

```json
{"dev":"line1-vib-1","boot":1,"seq":4182,"ts":"2026-11-23T08:41:20.123Z",
 "qty":"vib","val":3.12,"unit":"mm/s"}
```

| Поле | Тип | Одиниця / формат | Призначення | Діапазон |
|---|---|---|---|---|
| `dev` | рядок | `<лінія>-<пристрій>` | пристрій; має збігатися з темою | — |
| `boot` | ціле | ≥ 1 | номер запуску сенсора | ≥ 1 |
| `seq` | ціле | ≥ 0 | порядковий номер у межах запуску; виявляє пропуски й дублікати | ≥ 0 |
| `ts` | рядок | UTC, мілісекунди, `…Z` | момент вимірювання; для затримки | не з майбутнього (> 5 с) |
| `qty` | рядок | `vib`, `speed`, `temp` | величина | — |
| `val` | число | за `unit` | значення | vib 0–50, speed 0–5, temp −40…150 |
| `unit` | рядок | `mm/s`, `m/s`, `Cel` | одиниця | відповідає `qty` |

Сенсори області 9 (табл. 4 методички): вібрація, мм/с; швидкість конвеєра, м/с;
температура двигуна, Cel. **Межі діапазонів у collector.py треба звірити з реєстром
даних ЛР 1.**

## Політика оброблення помилок

| Ситуація | Як виявляється | Дія | Де фіксується |
|---|---|---|---|
| Не JSON, немає поля, хибний тип | перевірка за схемою (`validate`) | відхилити, роботу не зупиняти | `rejected`, причина |
| Одиниця не відповідає величині; `dev` не відповідає темі | перевірка за схемою | відхилити | `rejected` |
| Значення поза діапазоном сенсора | межі з даташита | відхилити як недостовірне | `rejected` |
| Мітка часу з майбутнього | більше ніж на 5 с від годинника сервера | відхилити; перевірити синхронізацію годинників | `rejected` |
| Дублікат | трійка (`dev`, `boot`, `seq`) уже є | не зберігати повторно | `anomalies`, `dup` |
| Пропуск n > 0 за (1) | `seq − last − 1 > 0` | зберегти показ, врахувати втрату | `anomalies`, `gap` |
| Позачерговий показ n < 0 | номера ще немає в `readings` | зберегти; пропуск зменшується | `anomalies`, `late` |
| Перезапуск сенсора | новий `boot` | почати лік номерів заново | `readings` |
| Сенсор зник | заповіт `offline` у темі `…/state` | брокер позначає пристрій недоступним | збережене повідомлення стану |
| Розрив зв’язку з брокером | `on_connect` після перепідключення | підписатися знову; покази QoS 0 за час розриву втрачено | пропуски в `anomalies` |

## Перевірка каналу

Канал перевірено внесенням збоїв: емулятор працював 30 с із частотою 20 Гц на
кожному з трьох сенсорів (λ = 60 повідомлень/с), частки збоїв `DROP` = 0,03,
`DUP` = 0,02, `LATE` = 0,03, `BAD` = 0,02.

```
DROP=0.03 DUP=0.02 LATE=0.03 BAD=0.02 HZ=20 DURATION=30 python smart/sensors.py
python smart/stats.py
```

Підсумок емулятора:

```
Підсумок: {'published': 1752, 'drop': 48, 'dup': 35, 'late': 46, 'bad': 28}
```

Результат `stats.py`:

```
boot rate sent received   loss late dup lat_mean_ms lat_p95_ms lat_max_ms
   1 60.0 1800     1752 0.0267   46  35         2.6          2        114
Відхилено: не JSON — 28
```

| Показник | Внесено | Виявлено підписником |
|---|--:|--:|
| Пропуски | `drop` = 48 | `sent − received` = 1800 − 1752 = 48 |
| Позачергові покази | `late` = 46 | `late` = 46 |
| Дублікати | `dup` = 35 | `dup` = 35 |
| Зіпсовані повідомлення | `bad` = 28 | «не JSON» = 28 |

Частка втрат за (2): ε = 1 − 1752 / 1800 ≈ 0,0267, що відповідає частці внесених
пропусків (48 / 1800). Затримка доставки за (3): середня 2,6 мс, 95-й процентиль
2 мс, найбільша 114 мс.

**Висновок.** Усі внесені збої збігаються з виявленими: підписник за номерами
(`dev`, `boot`, `seq`) розрізняє пропуски, дублікати й позачергові покази, а за
схемою відхиляє зіпсовані повідомлення, не зупиняючи роботу.
